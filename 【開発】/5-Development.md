# 5-Development（開発）

## 1. センサーやモジュールごとの検証
  
使用するマイコンとセンサーなどを購入，
ブレッドボード上で1対1で接続し，
動作を確認する．

### (例) 検証するモジュール
- 気圧センサー
- 9軸センサー
- GPS
- 磁気式エンコーダー
- microSDカードモジュール
- 差圧センサー
- 超音波センサー


## 2. 各電装部ごとに同時接続

基本，マイコンは各電装部ごとに1つでいい．
しかしながら，"1."で実施した検証でうまく動いても，
同時に複数のセンサーやモジュールを稼働させたことで
初めて発生する問題もある．

例えば，SDカードへの書き込みや
スピーカーの制御には時間がかかる場合がある．
これが各電装部同士の通信を遅らせたり，不安定にさせたりする．
そういった場合は，強引ながら確実な
「マイコン増設」という手段を取ることもできる
（当然，ソフトウェアを最適化することによって解決しても良い）．

ここでは，各電装部ごとに安定して動作させられるかを
ブレッドボード上で検証する．

また，これらの電装がどれくらいの空間を占めるか把握し，
コックピットのどの位置に搭載できそうか目星をつけておく．

### （例）26代エアデータ兼メイン電装部 - 構成
```
中枢マイコン ┬─ 差圧センサー（ピトー管）
　　　　　　 ├─ 気圧センサー
　　　　　　 ├─ 磁気式エンコーダー × 2
　　　　　　 └─ 補助マイコン
　　　　　　 　　 └ microSD カードモジュール
```

## 3. 各電装部を接続・同時動作
  
ここでは，鳥科の例年の方針に則り，
基板間通信はUARTによる文字列通信で，
中枢マイコンに全てのデータを集めることを想定する．
また，集めたデータはカンマ区切りの文字列に変換し，
UARTで返送，
各電装部のmicroSDカードモジュールで
保存できるようにする（冗長な構成にする）．

中枢マイコン ↔ 各電装部のマイコン のUART通信用ピンを接続する．

各電装部のマイコンでは，以下のような動作ができるようにする．
1. 各センサーから集めたデータを
  `sprintf()`関数などを用いて，
  カンマ（`,`）区切りの文字列に変換
2. `Serial1.print()`などでUARTにより文字列を送信
  （`Serial1.printf()`を使えば"1."を省略できる）
3. （中枢マイコンから返送されたデータをそのままmicroSDカードに保存）※ 脱落の心配が少ない，安全な基板を選ぶべきである

中枢マイコンでは，以下のような動作ができるようにする．
1. 各電装部から受信したデータを`TORICA_UART`を利用して分解
2. 基板上のセンサーからもデータを収集
3. 計算，補正
4. 全てのデータを連結した文字列を生成
5. 基板上のmicroSDカードに保存
6. 各電装部へ返送

全てのデータを連結すると非常に長い文字列になるので，数回に分けてUART通信しなければならない．

## 4. 搭載場所の検討
  
以下のような点に注意して検討する必要がある．
- 物理的に十分な安定性があるか．
- パイロットとの距離が十分に離れているか．

取り付け位置が大事になるセンサーもある．
- ベーン式AoA,AoSセンサー：翼やコックピットから十分離れた位置
- ピトー管：翼やコックピットから十分離れた位置

数値流体力学/流体解析（CFD）をおこなえるシミュレーションソフトウェアを用いて搭載位置を検討すると良い．  
ただし，操作が難解で時間もかかるので，流体力学の「境界層理論」に基づいて影響範囲を考えるだけでも十分かもしれない．
